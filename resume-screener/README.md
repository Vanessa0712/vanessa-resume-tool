# Resume Screener — 简历技能批量筛选工具

把「打分卡 + 漏斗筛选」方法论工程化：**硬性门槛过滤 + 核心技能加权评分排序**，一条命令处理整个简历目录，输出排名表与 CSV 报告。

## 快速开始

```bash
# 零依赖即可运行（txt / md / docx）
python resume_screener.py --config requirements.json --dir resumes --out screening_report.csv

# 需要 PDF 支持时（可选）
pip install pypdf
```

## 它怎么筛选（与人工漏斗一致）

```
简历目录 → 文本抽取 → ① 硬性门槛（必备技能/年限，不过直接淘汰）
                      → ② 加权评分（核心技能 90 分 + 加分项 10 分）
                      → 排序输出（通过 > 待核实 > 淘汰，同状态按总分降序）
```

**评分规则**：每个技能按关键词出现次数打分（0-5 分），再按权重归一：

| 关键词出现次数 | 评分 | 含义 |
|---|---|---|
| 0 次 | 0 | 未提及 |
| 1 次 | 2 | 仅罗列，存疑 |
| 2-3 次 | 4 | 项目里用过 |
| 4+ 次 | 5 | 深度实践 |

## 配置说明（requirements.json）

| 字段 | 作用 | 示例 |
|---|---|---|
| `position` | 岗位名，仅用于报告标题 | `"Python 后端工程师"` |
| `hard_gates.required_skills` | 必备技能，缺失直接淘汰（须在 core/nice 中有定义） | `["python", "sql"]` |
| `hard_gates.min_years` | 最低年限；简历未声明时进入「待核实」 | `3` |
| `hard_gates.strict_years` | `true` 时未声明年限直接淘汰 | `false` |
| `core_skills.<name>.weight` | 核心技能权重（占 90 分池） | `30` |
| `core_skills.<name>.aliases` | 触发别名，命中任一即算证据 | `["python", "python3"]` |
| `nice_to_have` | 加分项（占 10 分池） | 同上结构 |

**换岗位 = 改一份 JSON**：前端、测试、数据岗都只需重写技能清单与权重。

## 输出

- **控制台**：排名表（状态/总分/年限/逐技能证据数/淘汰原因）
- **CSV（utf-8-sig）**：Excel 双击直接打开；每份简历一行，含每个技能的证据次数，可二次排序过滤

## 已知限制（定位是「初筛排序」，不是「替你决策」）

| 限制 | 说明 | 缓解方式 |
|---|---|---|
| 关键词 ≠ 真实能力 | 技能罗列可以刷关键词 | 排名前列者走笔试/技术面复核 |
| 换表述会漏判 | "写接口" 不含 "REST" | 别名表尽量覆盖同义说法，定期补充 |
| 中文数字年限不识别 | "五年经验" 抽不出 5 | 建议简历模板统一阿拉伯数字；或落「待核实」 |
| PDF 依赖排版质量 | 双栏/图片型 PDF 抽取不全 | 需 `pip install pypdf`；关键候选人人工复核 |
| docx 为简化解析 | 忽略页眉页脚与表格顺序 | 常规简历足够 |

## 合规提醒

简历属于**个人敏感信息**：批量存储时注意目录权限管控；淘汰简历设定保留期限定期清理；外发报告前先脱敏（姓名/手机号/身份证）。

## 文件结构

```
resume-screener/
├── resume_screener.py     # 主工具（单文件，标准库实现）
├── requirements.json      # 岗位技能配置（改这份即可换岗位）
├── resumes/               # 示例简历（4 份，覆盖全部筛选结果）
├── screening_report.csv   # 运行产出的 CSV 报告
└── README.md
```
